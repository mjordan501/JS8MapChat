Current version: 1.6.0   (2026-07-15)   "shared-resolver"
  #35 is an internal refactor, not a version bump -- APP_VERSION stays "1.6.0"
  and the shared_resolve.log line still reads  version : 1.6.0  frozen=True.

  *** MILESTONE (#35 CLOSED): JS8Map's shared-dir resolver and JS8FastChat's are
      now ONE algorithm. Both apps proven frozen, launched from their DESKTOP
      SHORTCUTS, resolving the SAME mailbox character-for-character. ***

  CHANGE (#35) JS8Map's shared-folder resolver and FastChat's were two divergent
    copies of the "same" algorithm -- reversed env-var precedence, different
    walk-up anchor counts (JS8Map 4, FastChat 2), a legacy pointer-file step only
    JS8Map had (js8map_writer_path.txt), and different last-resort return types.
    Called "identical" for weeks; they were not (architecture doc, H6). Two copies
    of a contract edited by two separate programs is the shape of nearly every bug
    in this project.

    THE MERGE: the search ALGORITHM now lives in ONE module, shared_resolver.py,
    placed as TWO byte-identical twins -- one beside JS8Map.py, one in
    js8fastchat\. A build-time hash-gate (check_twins.bat, called by both build
    scripts) REFUSES TO BUILD if the two copies differ, so they cannot drift
    unnoticed. JS8Map keeps only a THIN ADAPTER (JS8Map.py:205-237) that hands the
    resolver its own four anchors (_EXE_DIR, _APP_DIR, _DATA_DIR, cwd) and
    preserves JS8Map's contract EXACTLY: _fc_shared_dir_impl() still returns
    (path_str, rule), path '' on total failure, so the public _fc_shared_dir()
    wrapper, its #42 logging, and all 7 call sites (which do `... or _DATA_DIR` /
    `if not shared`) are UNCHANGED.

  IMPORT NOTE -- JS8Map was NOT bitten by the frozen-import bug that hit FastChat
    this session. JS8Map imports the twin DOTLESS (JS8Map.py:217,
    `import shared_resolver`) and that is CORRECT: JS8Map is a FLAT FOLDER, not a
    package, so the twin sits on sys.path. (FastChat's copy lives inside the
    js8fastchat package and needed `from .shared_resolver ...`; that one-dot fix
    is FastChat's, commit c9f0322.) DO NOT ADD THE DOT HERE -- it re-breaks
    JS8Map. Proven: JS8Map's exe launched clean from its shortcut and logged the
    right SHARED DIR, twice, this session.

  VERIFIED (2026-07-15) -- do not re-test:
    - JS8Map.exe rebuilt 12:22 local on the merged resolver; launched FROZEN from
      its desktop shortcut, map generated first (a resolver test with no map has
      no server and no data -- invalid).
    - Both apps FROZEN from DESKTOP SHORTCUTS, callsign clicked -> FastChat popup
      -> grid query TRANSMITTED. Both shared_resolve.log read side by side,
      identical SHARED DIR:
          [JS8Map]   16:25:20 UTC  SHARED DIR = ...\JS8MapChat Shared Ver 1.5  frozen=True
          [FastChat] 16:41:57 UTC  SHARED DIR = ...\JS8MapChat Shared Ver 1.5  frozen=True

    ** SCOPE OF THE PROOF: this proves agreement in ONE layout -- sibling folder,
    this machine, the walk-up rule firing for both. It does NOT prove the
    resolvers agree on a stranger's machine (Program Files, or one env var set),
    where a DIFFERENT rule fires. "Proven in the realistic layout," not
    "proven everywhere."

  GIT: the shared merge is commit c9f0322, tagged v1.6.0-35-shared-resolver-proven
    (the repo-wide tag covering both apps; JS8Map's adapter edit is part of it).
    ROLLBACK: git checkout v1.6.0-both-frozen-proven (pre-#35 entirely) or
    v1.6.0-35-shared-resolver-proven (this proven state).

  KNOWN COSMETIC (not fixed, noted): Build_JS8Map.bat (renamed from Build_JS8Map_v1.83.bat) prints

1.6.0   "version-free-folder"   (#38)
  A 1.6.0 companion to the "shared-resolver" (#35) milestone above; shipped
  as part of the same unification. Code present in the shipped tree,
  HEAD-verified this session at the lines cited. Documentation only -- no
  code change here.

  CHANGE (#38) The shared-mailbox folder name is now VERSION-FREE. Canonical
    name 'JS8MapChat Shared'; the legacy 'JS8MapChat Shared Ver 1.5' is still
    ACCEPTED, in priority order (JS8Map.py:191-192, _FC_SHARED_DIR_NAMES).
    An existing install keeps working with no rename by the operator.

  WHY In v1.5 the two apps agreed on the mailbox by string-matching a folder
    name with the version baked in ('...Ver 1.5'). That made a version bump a
    BREAKING CHANGE to the contract between two separately built programs:
    rename the folder, bump one app's constant but not the other's, and the
    handoff dies -- silently, in a --noconsole build. Taking the version out
    of the name means the next bump never touches the contract.
    (JS8Map.py:174, "v1.6: THE VERSION IS OUT OF THE FOLDER NAME.")

  DEAD CONSTANT (deliberate) _FC_SHARED_DIR_NAME = 'JS8MapChat Shared'
    (JS8Map.py:184) is read by NOTHING and creates the folder from NOTHING.
    Kept only so no stale import can break. When the sibling shared folder is
    absent the per-user mailbox is used; JS8Map never creates a sibling.

  MIRRORS FastChat's parallel folder-name contract -- its accepted-names list
    must stay identical (verify_shared_dir.py asserts it; the twin hash-gate,
    check_twins.bat, enforces the shared_resolver.py copy).

1.6.0   (audit closed 2026-07-16)   "datadir-fix"   (#40)
  Partial _DATA_DIR->shared moves shipped inside 1.6.0; this session AUDITED
  the remainder and confirmed BOTH sides. No code change resulted -- the
  finding was that the write side was already correct. NOT a "reorg done"
  claim; this is an audit closure. (Companion to FastChat's own 1.6.0
  "datadir-fix" block.)

  CHANGE (#40) Three cross-app handoff files moved from JS8Map's per-user
    _DATA_DIR to the SHARED mailbox, resolved shared-first (tagged
    "v1.6: was _DATA_DIR"):
    - js8fastchat_intent.json     (JS8Map.py:4104)
    - js8map_raise_fastchat.json  (JS8Map.py:4145)
    - js8map_server.json          (JS8Map.py:4291)
    each os.path.join(_fc_shared_dir() or _DATA_DIR, ...). WHY: in SCRIPT
    mode _DATA_DIR is JS8Map's source folder, which FastChat's poller does
    not search, so the handoff only ever worked from the frozen .exe. The
    shared folder works in both modes and in the installed build.

  AUDIT (2026-07-16, HEAD-verified) Walked all 33 _DATA_DIR uses in
    JS8Map.py. RESULT: every file that crosses the app boundary already
    resolves shared-first (the three above, plus the outgoing-TX publish and
    the TX-pending lease, and the read of FastChat's js8fastchat_alive.json).
    Every REMAINING _DATA_DIR use is genuinely JS8Map-PRIVATE and correctly
    stays per-user: js8_spots.db, js8_relay.db, js8_groups.json,
    ham_map_config.json, the ham_map.html render output, tx_shadow.log,
    map_window_profile, the app icon, and the debug logs. No cross-app file
    is stranded on the per-user folder. The "#40 ZERO ROWS" failure does NOT
    occur in the shipped build.

  FALLBACK IS SAFE, NOT A BUG The 'or _DATA_DIR' fallback fires only if
    _fc_shared_dir() returns '' (total resolver failure). Even then, in the
    frozen build FastChat still finds the file: intent_poller._search_dirs()
    -> _newest_existing() searches the resolved shared dir, the per-user
    mailbox %LOCALAPPDATA%\JS8MapChat\Shared (ALWAYS), and legacy
    %LOCALAPPDATA%\JS8Map (a frozen JS8Map's _DATA_DIR), and takes the
    NEWEST copy (FastChat's #34 stale-shadow fix). Confirmed by reading
    FastChat's poller this session.

  KNOWN LIMITATION (dev-only, never shipped) The single uncovered corner is
    SCRIPT mode AND resolver-empty at once: there _DATA_DIR is JS8Map's
    source folder, which the poller does not search, so a fallback write
    would be missed. This cannot happen in the frozen / installed product.
    Not fixed; documented.

  SCOPE (mirrors #35's scope note) #40 is proven for the REALISTIC layouts
    on both the write (JS8Map) and read (FastChat) sides -- "proven in the
    realistic layout," not "proven on every possible machine."

  GIT No code change from the audit; the moved-file code is part of the
    shipped 1.6.0 tree (HEAD-verified at the lines above). This changelog
    entry is the deliverable.

Current version: v1.82_A
New in v1.82_A:

    all relay timers cancelled, and armed_target/armed_target_pos stripped

v1.81 consolidates the v1.80_B..v1.80_F release-candidate series into a
stable build. Headline changes since v1.80:
  • TX MODE (Shadow / Manual / Live) governs Group GO + Relay Search, with a
    persisted startup default (config 'tx_mode', never auto-live), a settings
    radio, a mid-session "↻ Change" flip, an always-visible colour readout,
    and a confirm prompt EVERY time Live becomes active. Relay Phase-2 GO is
    exempt and always stages.
  • Phase-2 relay staging via tx_stage()/TX.SET_TEXT — fills JS8Call's box
    (never transmits) + clipboard backup; operator sends the real message.
  • TX status feedback: status lines report what actually happened
    (transmitted LIVE / filled box MANUAL / not connected / shadow).
  • Relay reliability: discovery rebuilds the map so vias plot live; home
    station no longer hidden; "Refresh paths" button; return-leg watchdog
    (timeout_return → Switch Path) for when a via never relays the reply home.
  • Relay callsign field rewritten to an airtight placeholder model — the
    2nd-callsign mangling bug ('EKGC1PHY') is eliminated at the root.
  • UI: gold "Startup TX" settings label.

Known open item (deferred to a future version):
  • Clear/QSY does not yet tear down an armed relay target, so a stale target
    can briefly reassert after a frequency change until cleared with ×.

Detailed RC history follows.
─────────────────────────────────────────────────────────────────────
v1.80_F:
  FIX (root cause) relay 2nd-callsign mangling ('EKGC1PHY'): replaced the
    fragile in-StringVar placeholder with an airtight model — a <KeyPress>
    handler clears the placeholder BEFORE the typed char lands, and a write
    trace sanitizes every change to callsign-legal chars only. The placeholder
    can never coexist with input, so typing a second callsign after Search (or
    after the × clear) always yields a clean target. Arm guard also short-
    circuits when the placeholder is active. Verified: ke2kn→KE2KN, × clear,
    kc1phy→KC1PHY (not EKGC1PHY).
v1.80_E:
  TX feedback: tx_query now returns a status ('sent'/'staged'/'shadow'/'skip')
    and the relay-arm + group-Go status lines report what ACTUALLY happened
    ("transmitted (LIVE)" / "filled JS8Call box (MANUAL)" / "not connected"),
    instead of always saying "copied to clipboard". Makes mode behavior and
    connection problems self-diagnosing. Removed a stray duplicate return.
v1.80_D:
  FIX relay callsign field: placeholder ('e.g. KD4E') could concatenate with
    typed input on a focus race (e.g. 'KC1E.G. KD4E'), pass the old exact-match
    guard, and send a malformed QUERY CALL that JS8Call ignored — the cause of
    "relay didn't fire after reopen". Now: _relay_key strips placeholder
    fragments + keeps only callsign-legal chars; FocusOut/hide clears partial
    placeholder; arm guard validates the target (3–10 chars, has a digit) and
    rejects remnants so garbage never reaches tx_query.
  UI: "Startup TX" settings label is now gold + bold to stand out.
v1.80_C:
  TX MODE feature — Shadow / Manual / Live, governs Group GO + Relay Search:
    - shadow: log only (no JS8Call touch); manual: TX.SET_TEXT (fills box, no
      RF, operator sends); live: TX.SEND_MESSAGE (real RF).
    - Saved startup default in config ('tx_mode'); missing/corrupt → 'manual'.
      NEVER auto-defaults to live.
    - Settings card: "Startup TX" radio (Shadow/Manual/Live), persists.
    - Mid-session "↻ Change" flip (Shadow→Manual→Live) without restart.
    - Always-visible on-screen readout (🔴 SHADOW / 🟡 MANUAL / 🟢 LIVE).
    - Going LIVE prompts a confirm EVERY time (including at startup); decline
      falls back to manual.
    - Relay Phase-2 GO is EXEMPT — always stages (TX.SET_TEXT) in every mode.
v1.80_B:
  Phase-2 relay staging: GO now stages the relay frame instead of sending it.
    - tx_stage() chokepoint uses TX.SET_TEXT (fills JS8Call's outgoing box,
      NEVER transmits) + clipboard copy as backup. Operator types the message
      in JS8Call and presses send manually — human checkpoint on the one frame
      that carries real content.
    - tx_stage is EXEMPT from the shadow gate (TX.SET_TEXT is RF-safe by
      design); the real transmit path (tx_query / TX.SEND_MESSAGE) stays gated.
  Return-leg watchdog: timeout_return fires if the via gets the target's reply
    but never relays it home (Switch Path popup, mirrors timeout_dest).
  Relay discovery now rebuilds the map (vias plot live); home station no longer
    hidden during relay; "Refresh paths" button added to relay banner.
Key features delivered in C.18 series:

  fitAll auto-fires on Done exit; api_log preserved across restarts
  R button replaced with full JS8Call snapshot refresh
  Animation on/off toggle; Watched Calls filter; Groups moved to row 1
  Light-map line visibility improved (weight 2.8, opacity 0.75)
  Reset Relay (was Clear Relay); Clear button removed (redundant with Done)
